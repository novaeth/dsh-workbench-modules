# @dsh-workbench/module-creator-daily

内容创作者的一天：**今日选题 → 我的笔记数据 → 存草稿**。

v0.1 只有卡片接线，数据与工具在 v0.2 接入；这一版的意义是把模块的位置、清单、构建与门禁先定下来。

## 你会看到什么

右侧面板多一张「内容日更」卡片，标题下面一行是这条工作流的三个动作，再一行是当前版本说明。

卡片之外没有别的界面：这一版没有设置项、没有审批、没有 agent 工具。

## 安装

模块市场发布之前，先在仓库里构建：

```bash
pnpm install
pnpm -r build
```

然后在工作台里按模块市场的本地安装方式接入（`dist/host.js` 是宿主入口，`client.js` 是浏览器入口）。

## agent 能做什么

v0.1：没有开放工具，agent 看不到这个模块。

v0.2 计划（对应 opencli 官方适配器的读命令）：

| 能力 | 读什么 | 是否要批准 |
|---|---|---|
| 今日选题 | `zhihu hot` / `weibo hot` / `bilibili hot` | 只读 |
| 我的笔记数据 | `xiaohongshu creator-stats` / `creator-notes` | 只读 |
| 存草稿 | `xiaohongshu publish --draft` | 需要批准 |

## 数据从哪来

- 三个热榜与小红书创作者中心都走 opencli 官方适配器，复用浏览器里已登录的会话；模块自己不保存账号密码。
- 需要先登录对应站点一次；登录过期时卡片要能区分「没登录」与「没有数据」。
- v0.2 才有数据源，所以现在没有任何网络请求。

## 审批

v0.2 的「存草稿」会先弹审批，四行固定为：

- 对象：小红书 · 一条新笔记（草稿）
- 修改后：标题 + 正文 + 话题 + 图片张数
- 目标位置：当前账号的草稿箱
- 影响范围：只存草稿，不发布

## 边界（v0.2 的已知风险）

- 小红书发布走 creator center 的 UI automation，平台改版会失效。
- 标题最多 20 字、图片最多 9 张，超出在命令侧就会失败。
- 只做「存草稿」，正式发布要人工在平台点。

## 手工验收（v0.2 起）

1. 在浏览器里登录知乎、微博、B 站、小红书。
2. 打开工作台，勾选「内容日更」，卡片出现三个热榜条目。
3. 让 agent 读一次选题，确认它引用的条目与卡片一致。
4. 让 agent 存一条草稿，确认审批四行与内容，点「允许」后到小红书草稿箱核对。
